## Interview Stories

### Tell me about your data analysis project.

Structure:

1. Business problem.
2. Data sources.
3. Modeling approach.
4. Analysis performed.
5. Dashboard decisions.
6. Key recommendation.
7. What you would improve next.

### How did you ensure data quality?

Talk about:

- Source profiling.
- Primary key and foreign key checks.
- Null and accepted value tests.
- Row count reconciliation.
- Metric reconciliation between source and mart.
- Data quality dashboard page.
- Known limitations.

### How did you design the Power BI model?

Talk about:

- Star schema.
- Date dimension.
- Fact table grain.
- Dimension relationships.
- DAX measure table.
- Avoiding ambiguous relationships.
- Tooltips and drillthrough.
- RLS demo.

### How did you handle ambiguous requirements?

Talk about:

- Problem brief.
- Stakeholder map.
- Business questions.
- KPI dictionary.
- User stories.
- Acceptance criteria.
- UAT tests.
- Traceability.

### What makes this different from a normal dashboard project?

Answer:

- It covers the full analytics lifecycle.
- It uses cloud datasets and deployable tools.
- It includes data quality and documentation.
- It is multi-domain.
- It has BA artifacts and executive recommendations.
- It is interview-ready with reproducible code.

## Role-Specific Talking Points

### Data Analyst

Emphasize SQL, Python EDA, cohort/funnel analysis, statistics, and recommendations.

### BI Analyst

Emphasize Power BI model design, DAX, dashboard UX, deployment, refresh, and metric documentation.

### Business Analyst

Emphasize stakeholder requirements, process thinking, user stories, UAT, and business outcomes.

### Junior Analytics Engineer

Emphasize dbt, staging/marts, tests, lineage, cloud warehouse, and data model design.
